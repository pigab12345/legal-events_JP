# 追加機能の導入手順（完全自動更新版）

## 1. ファイル配置
このフォルダの中身を repo にそのままコピーしてください（同名ファイルは上書き）。
- `data/sources.json` … 巡回対象サイト一覧（**実在URLに書き換えてください**）
- `data/candidates.json`, `data/geocache.json`, `data/rejected_sources.json` … 空の初期ファイル
- `scripts/crawl_and_structure.py` … 巡回＋AI構造化＋自動登録
- `scripts/promote_candidate.py` … 誤登録を手動で削除・修正するための補助ツール（通常は使いません）
- `.github/workflows/crawl-and-structure.yml` … 約2週に1回自動実行するワークフロー（**events.jsonを直接更新**）
- `.github/workflows/promote-candidate.yml` … 手動修正用ワークフロー（通常は使いません）
- `index.html` … 行きやすさランキング・ステータスバッジ対応版（既存を置換）

## 2. GitHub Secrets 設定
`Settings → Secrets and variables → Actions` で以下を追加:
- `ANTHROPIC_API_KEY`（必須）: Claude APIキー
- `DISCORD_WEBHOOK_URL`（任意）: 通知を受け取りたい場合のみ

## 3. GitHubリポジトリ設定（重要・初回のみ）
`Settings → Actions → General → Workflow permissions` で
**「Read and write permissions」** になっていることを確認してください
（`contents: write`でのpush・Issue作成に必要です）。

## 4. 動作の流れ（すべて自動・人間の確認ステップなし）

1. 毎月1日・15日 JST 6:00 にワークフローが起動（約2週に1回。`workflow_dispatch` で手動実行も可）
2. **新規サイトを自動発見**: 「弁護士会」「法律事務所」「学会・研究会」「公開講義・市民講座」「受験生・修習生・就活」の5カテゴリに分けてClaude APIのWeb検索機能で探索し、`sources.json`にまだ無いサイトを自動追加（1カテゴリあたり最大6件・1回の実行で最大25件まで）
3. 各サイト（既存＋新規発見分）を巡回 → Claude APIでイベント候補をJSON化
4. **開催日が既に過去のイベントはこの時点で除外**（掲載しません）
5. 既存 `data/events.json` と突合し、新規登録／日程変更／中止／申込開始を検出
6. **`data/events.json` に直接反映**（自動登録・人間の確認は挟みません）
7. **開催日が過ぎた既存イベントも自動的に削除**（サイトが常に最新状態に保たれます）
8. 変更があれば `main` ブランチへ直接コミット・push
9. 変更内容をGitHub Issueとして自動投稿（承認は不要。記録・通知だけの目的）
10. Discord Webhook設定時はそちらにも通知

### ⚠️ この設計の注意点
- AIの抽出ミス（誤った日付・誤った参加可否判定など）が**そのままサイトに反映される**可能性があります
- 明らかな誤りに気づいたら、`Actions`タブ →「イベントを手動修正」→ `Run workflow`で該当IDを`remove`してください
- `data/candidates.json`には毎回の抽出結果の生データが記録として残るので、後から「なぜこの情報が載ったか」を追跡できます

### 見つけてほしくないサイトを除外する
自動発見が明後日の方向のサイトを拾ってきた場合、`data/rejected_sources.json` にURLを追加してください。

```json
["https://example.com/irrelevant-page"]
```

## 5. 誤登録の手動修正（Python不要・スマホのみ）

1. `data/events.json` または `data/candidates.json` をGitHub上で開き、対象の `id` を確認
2. `Actions` タブ → 「イベントを手動修正」→ `Run workflow`
3. `candidate_id` にid、`action`は通常 `remove`（削除）を選択
4. 実行すると自動で `data/events.json` が更新される

## 6. 「行きやすさランキング」について
- クロール時に会場を無料のジオコーディングAPI（Nominatim）で緯度経度化し、東京駅・横浜駅からの直線距離を算出・保存します。
- あくまで直線距離の目安であり、実際の乗換時間ではありません。
- オンライン開催は「移動不要」として常に上位表示されます。

## 8. 対象イベントの範囲について
専門的な学会・シンポジウムだけでなく、以下も収集対象です:
- 公開講義・市民向け法律講座
- 司法試験・予備試験受験生向けガイダンス
- 司法修習生向け説明会
- 法曹（弁護士・検察官・裁判官等）志望者向けの就活・進路説明会、業務説明会、インターンシップ情報

各イベントには `category` フィールド（学会・専門シンポジウム／公開講義・市民講座／受験生向けガイダンス／就活・進路説明会／その他）が付与され、
サイト上部の「種類」セレクトやチップで絞り込み表示できます。

## 9. 今後の拡張候補
- 巡回対象を「一覧ページ」だけでなく個別イベント詳細ページまで再帰的に辿る
- Directions APIによる実際の所要時間ベースのランキング
- 誤登録が多い場合、confidence="要確認"のものだけ自動登録せずcandidates.jsonに留める、といったハイブリッド運用への切り替え

## 10. 探索の網羅性とコストについて
自動発見は「弁護士会」「法律事務所」「学会・研究会」「公開講義・市民講座」「受験生・修習生・就活」の
5カテゴリに分けて別々に検索するため、1回のカテゴリにつきWeb検索を最大6回行います
（1回の巡回実行で最大30回程度）。実行頻度を2週に1回に減らしたことで、月あたりのコストは
むしろ以前（毎日・単一カテゴリ探索）より抑えられる見込みです。

## 11. コスト削減の工夫（結果は変えず、無駄だけを削る）
今回のバージョンから、抽出結果を変えずに以下でコストを抑えています:

1. **Adaptive Thinkingを無効化**: Claude Sonnet 5はデフォルトで内部推論（見えない思考過程）にも
   出力トークン課金が発生します。このアプリは構造化JSONの出力だけが目的で推論過程の開示は不要なため、
   `thinking: {"type": "disabled"}` を全呼び出しに設定し、この分のコストを削減しています。
2. **プロンプトキャッシュ**: イベント抽出の指示文（毎回同じ内容）を `cache_control` でキャッシュ対象に
   設定。5分以内に連続して呼び出すと、2回目以降はその指示文部分が割引価格で処理されます
   （ただし指示文がAnthropic側の最小キャッシュサイズ未満の場合は効果が出ないことがあります。
   その場合も動作・結果には影響ありません）。
3. **安価モデルの使い分け**: サイト自動発見の「検索メモをJSONに整形するだけ」の機械的な処理は、
   判断力を要さないため `claude-haiku-4-5-20251001`（Sonnet 5よりも安価なモデル）に担当させています。
   実際の検索・判断が必要な工程は引き続きSonnet 5が担当するため、精度は変わりません。
4. **整形フェーズの呼び出し回数を5回→1回に統合**: 従来はカテゴリごとに整形API呼び出しをしていましたが、
   全カテゴリの検索メモをまとめて1回で整形するようにし、指示文の重複送信を削減しました。

ログの `[INFO] キャッシュヒット: ○○トークン分を割引価格で処理` という行が出ていれば、
キャッシュが実際に効いている証拠です。

## 12. 今回の変更点
- **バッジの重なりを解消**: 右上に絶対配置されていたバッジ（距離表示含む）を、タイトル上部の通常フロー表示に変更。距離の数値表示自体は削除し、住所（`place`）表示のみに簡素化（東京駅・横浜駅からの近い順ソート機能自体は内部的に残しています）
- **新着表示**: 各イベントに初回登録日時（`added_at`）を記録し、直近約2週間以内に追加されたイベントに「🆕 新着」バッジを表示
- **新着順ソート**: 「種類」の右のソートに「新着順（リストアップ日）」を追加
- **コスト削減（ページ未変更時のAI処理スキップ）**: `data/page_hashes.json` に各巡回ページの内容ハッシュを保存し、前回巡回時から**ページ内容が一切変わっていない場合はAI抽出そのものをスキップ**します。ページが同一なら抽出結果も同一のはずなので、精度を変えずに呼び出し回数を削減できます（2週間隔の巡回では、多くのページが変化しないため効果が大きいはずです）
- **通知機能を削除**: GitHub Issue通知・Discord通知のステップをワークフローから削除しました。`DISCORD_WEBHOOK_URL`のSecretsはもう不要です（設定済みでも害はありませんが、削除して構いません）
